Docker, agents, tokens and templates

1 GitHub access

A personal access token with repo and project scopes. Stored locally in ~/.flywheel.

2 Project board

The GitHub Projects board the factory watches for work.

3 Agents & options

Every feature branch is cut from this branch's latest commit, and every pull request goes back into it. A repository that does not have it falls back to its own default, so master and dev repositories keep working.

4 Templates

Used only when a repository has no code yet. A repository that already has code is never scaffolded — its own structure is followed instead.

One template is one folder: template.yml describing it, a template/ folder with the files that get committed, and an optional guidance/ folder with the rules, samples and architecture tests the agents read — staged into the working copy, never committed. Your folder wins when an id matches a bundled one.

5 Docker host & preview environments optional

A Docker host reached over SSH gives every pull request a live URL and screenshots. Leave blank to skip previews.

6 Notifications optional

Get the preview link and screenshots on Telegram when a PR is ready. Paste your bot token, then message your bot once (press Start) and enter your @username — Flywheel finds your chat id automatically. Or paste a numeric chat id directly.

Project brief and plan

Loading the connected GitHub Project…

Each selected agent researches the repository and the brief on its own; the plans are merged and tasks both agents proposed are listed first.

Backlog grooming

Every loop cycle, the factory reads the Todo cards from GitHub, and the agents re-read the repository and this brief to rewrite each card with scope, acceptance criteria, the tests it needs, its dependencies on the other cards and a shared branch/workstream where several must ship together. The rewritten text is written back to the GitHub issue, once per card, before anyone starts building it. Write issues however you like — the factory sharpens them.
